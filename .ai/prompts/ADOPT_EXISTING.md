# Prompt: Adopt Template into an Existing Repo

기존 프로젝트에 이 템플릿을 적용한다. **통째로 덮어쓰기 금지.**

1. 기존 `AGENTS.md`, `CLAUDE.md`, `.claude`, README, Requirements, UI/Architecture, Tests, Git 상태를 확인한다.
2. 이전의 확정 결정과 새 템플릿 간 충돌/중복 목록을 만든다.
3. 동작을 바꾸지 않는 서류 구조 통합만 먼저 제안하되 기존 파일을 삭제/덮어쓰지 않는다.
4. 원래 동작을 Characterization/Regression 기준으로 문서화하고 미검증은 미검증으로 표기한다.
5. 병합/이동/이름 변경/새 지침 우선순위는 사용자에게 구체적 Before/After와 함께 승인 요청한다.
6. 승인 후 관련 파일만 통합하고 테스트 결과/차이/원상복구 방법을 보고한다.

## 기존 코드를 다른 도메인으로 재활용할 때 (예: 강의 수강신청 코드를 입찰 서비스로)
코드를 고치기 전에 아래 표를 먼저 만들어 승인받는다. 충돌은 구현 후가 아니라 여기서 잡는 것이 싸다.
- 옛 모델 -> 새 모델 대응표(엔티티, 테이블, 서비스 책임).
- 같은 URL/경로가 서로 다른 의미로 쓰이는 곳. 컨트롤러를 그냥 추가하면 매핑 충돌로 기동하지 못할 수 있다.
- 화면 용어 <-> 저장/API 값 대응표(예: `낙찰` = `ACTIVE`). 옛 enum 값을 새 의미로 빌려 쓰면 의미가 어긋나므로 대응을 문서로 고정하고, AI에게 이 표를 함께 준다.
- 기존 데이터와 기능을 보존할지: 보존하려면 새 테이블 이름으로 분리한다.
